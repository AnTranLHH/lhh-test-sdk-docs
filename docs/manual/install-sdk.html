    Install the Test SDK

    This guide is for QA writing NUnit tests in the Unity Editor with LHH_TestSDK.

    Platform support: Android only today. iOS options in Settings are reserved for a later release—do not rely on iOS until documented otherwise.

    Requirements

    • Unity 2022.3 or newer (2022.3.67f2+ recommended).
    • A game project where the player build includes automation (see Player build below).
    • Bitbucket SSH access to LiHuHu repos (for UPM git URLs).

    1. Add the Test SDK package

    In the game project, edit Packages/manifest.json and add:

    "com.lhh.testsdk": "git@bitbucket.org:lihuhu/lhh-auto-test-sdk.git?path=Assets/TestSDK"

    Pin a release when dev specifies one, for example:

    "com.lhh.testsdk": "git@bitbucket.org:lihuhu/lhh-auto-test-sdk.git?path=Assets/TestSDK#v0.1.0"

    Open the project in Unity and wait for Package Manager to resolve the package.

    2. Run Install Test SDK in the Editor

    1. Open LHH Test SDK → Settings.
    2. Enable Show Advance Settings.
    3. Click Install Test SDK and wait until progress shows Test SDK install finished.

    This step:

    • Writes NuGet config under Assets/ and restores client packages (MagicOnion, MemoryPack, gRPC, etc.).
    • Merges required Unity Package Manager dependencies into Packages/manifest.json.
    • Adds the LHH_AUTOMATION_TEST scripting define so LHH_TestSDK and player hub code compile.

    You only need to run Install Test SDK again after a SDK update (see Updating after a release).

    3. com.lhh.testcontroller.shared (required)

    The shared contracts package (com.lhh.testcontroller.shared) is not something QA normally adds by hand. Install Test SDK merges it into manifest.json, for example:

    "com.lhh.testcontroller.shared": "git@bitbucket.org:lihuhu/lhh-auto-test-controller.git?path=src/Lhh.TestController.Shared"

    It contains MagicOnion service contracts and command DTOs used by:

    • Your NUnit tests (LHH_TestSDK in the Editor),
    • The InAppTestRunner code in the player build,
    • The Test Controller process on your machine.

    Editor, player, shared package, and running controller must all match the version dev released together. If they drift, you may see hub connection failures or RPC errors.

    Updating after a release

    When dev ships a new Test SDK:

    1. Update com.lhh.testsdk in manifest.json (new tag or commit on lhh-auto-test-sdk).
    2. Open LHH Test SDK → Settings → Install Test SDK again so installer-owned dependencies stay in sync.
    3. Update com.lhh.testcontroller.shared in manifest.json if release notes pin a new controller tag/commit (for example #v0.2.0).
    4. Ask the game team for a new Android APK built with the updated automation bits; update App path in Settings before running tests.

    Confirm in Window → Package Manager that both com.lhh.testsdk and com.lhh.testcontroller.shared are present.

    Player build (InAppTestRunner)

    Tests drive a real Android build on a device. That APK must come from a project that:

    • Includes the Test SDK package (which contains InAppTestRunner—hub + command executors for UI, scenes, PlayerPrefs, IAP, etc.).
    • Has LHH_AUTOMATION_TEST enabled for the Android build target (same define Install Test SDK adds for the Editor; the game team must include it on the player platform).

    At runtime the player should connect to the Test Controller hub (look for logs such as TestSDK: Create MagicOnionCommandHub Done in logcat when debugging).

    Bundle ID on the device build must match what you configure in Settings (Player Settings application identifier, or Bundle ID override).

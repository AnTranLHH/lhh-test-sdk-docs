    Test Controller and settings

    Android only for running tests today.

    Open Settings

    LHH Test SDK → Settings

    Values are stored in EditorPrefs on your machine (not in git). Each QA machine keeps its own gRPC address, app path, bundle id, and device preference.

    Configuration (always visible)

    Field Purpose
    gRPC server address Test Controller URL. Default: http://127.0.0.1:5050.
    Bundle ID Optional override. If empty, the effective id is Player Settings → Application identifier. Must match the installed APK.
    Platform Use Android for now.
    App path Required for setup. Full path to the automation-enabled .apk as the Test Controller host can read it (use Browse). If empty, the first setup call fails the test with an error—there is no silent continue.
    Release session after test run When enabled (default), the Test Runner returns the leased device when a full run finishes or the runner errors. Turn off to keep the lease between runs (see Release session now to return the device manually).

    Test device (device pool)

    Shown under Configuration when the test server is ready.

    Control Purpose
    Selected device (Any claimable device) or a specific device from the controller pool. This is a preference only—the lease happens on Connect test device or on the first LHH_TestSDK call in a test.
    Refresh device list Reloads claimable devices from the controller (devices already leased are omitted).

    Requires Test Controller installed and Run Test Server active. If the server is not running, the list is disabled and a warning explains why.

    Changing Platform while the server is running refreshes the device list automatically.

    Session & server

    Visible on the main Settings page (not hidden under Advance Settings).

    Control Purpose
    Connect test device / Re-sync test device Runs setup without the Test Runner: lease device (using Selected device if set), Appium session, hub wait. Label switches to Re-sync when the Editor domain already completed setup. Use while authoring tests so the first API call in a test is faster.
    Release session now Returns the leased device to the pool and clears Editor setup state immediately.
    Run Test Server / Stop Test Server Starts or stops Appium and the controller (gRPC 5050, Appium 4723). Shown after Install Test Controller succeeds.

    Domain reload: After you change scripts, Unity clears local SDK state. The controller may still hold the lease and an Appium session. Use Re-sync test device before the next test, or let implicit setup run on the first SDK call. If Appium reports a session already active but the wrong app is on the device, Stop Test Server or Release session now, then connect again.

    Updates

    Check for update compares three git sources with their remotes:

    Source What is compared
    com.lhh.testsdk Installed package revision, or this repo when the project is the Test SDK checkout
    com.lhh.testcontroller.shared Installed package revision in packages-lock.json
    Test Controller repo ~/lhh-auto-test-controller against origin of the current branch

    If any source is behind, Update appears. Otherwise the window reports that you are up to date. Stop the test server before updating the shared package or the Test Controller repo. After a Test SDK package update, run Install Test SDK again if installer-owned dependencies changed, and install a new player build before testing.

    Install Test Controller and Test SDK (Advance Settings)

    Enable Show Advance Settings at the bottom of the window:

    Control Purpose
    Install Test SDK NuGet/UPM merge and LHH_AUTOMATION_TEST (see Install the Test SDK).
    Install Test Controller Clones and prepares ~/lhh-auto-test-controller (environment check/setup).
    Progress Log output for install/setup.

    Typical order: Install Test SDK → Install Test Controller → Run Test Server (in Session & server) → set App path and device → Connect test device (optional) → run tests.

    If controller install fails, read Progress. Missing JDK, Android SDK, or Appium usually needs a one-time machine setup—coordinate with dev/infra.

    The running controller version should match com.lhh.testcontroller.shared in your Unity project (see Install the Test SDK).

    What happens during setup

    Whether you use Connect test device or the first LHH_TestSDK call in a test, setup:

    1. Opens a gRPC client to gRPC server address.
    2. Requests a device lease from the controller (with optional Selected device id). If leasing fails, the test stops immediately with the controller’s message (for example no free device).
    3. Appium session — if none is active for your bundle id, creates one using App path (must be set) and launches the APK. If a session is already active, creation is skipped (see warning in Console if the device state is wrong).
    4. Waits until the Unity player command hub connects.

    When the Test Runner finishes the whole run (or reports a runner error), the SDK calls Release session logic only if Release session after test run is enabled.

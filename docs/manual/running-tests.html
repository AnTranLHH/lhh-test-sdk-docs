    Running tests

    Android only until a future release documents iOS.

    Checklist before Run

    1. Test SDK installed in the project (Install the Test SDK).
    2. com.lhh.testcontroller.shared present and aligned with the SDK/controller version dev released.
    3. Install Test Controller done (Advance Settings) and Run Test Server active (Session & server on the Settings window).
    4. Android device connected (USB debugging); pick (Any claimable device) or a specific entry under Test device → Refresh device list.
    5. Settings filled in:
      • Platform: Android
      • App path: required — automation-enabled APK path valid on the controller machine (InAppTestRunner + LHH_AUTOMATION_TEST on Android)
      • Bundle ID matches the APK (override or Player Settings)
      • gRPC server address: http://127.0.0.1:5050 unless your machine uses another host/port
    6. Player build is the version QA expects (rebuild and refresh App path after SDK/shared updates).

    Optional: Connect test device in Session & server to complete setup before opening the Test Runner.

    Connect test device (optional, while authoring)

    Connect test device runs the same pipeline as implicit test setup (lease → Appium → hub) without the Test Runner. Useful when writing tests so the first LHH_TestSDK call in a run is quick.

    After script recompile, use Re-sync test device. The controller may still hold your lease; the Editor reconnects and reuses an active Appium session when possible.

    Release session now when you want the device back without stopping the whole test server.

    Run from Test Runner

    1. Window → General → Test Runner
    2. Select EditMode (or PlayMode if your team uses it for specific tests).
    3. Run one test, a fixture, or all tests.

    If setup already succeeded in this Unity domain (Connect test device or an earlier test), subsequent SDK calls skip setup until Release session now, domain reload, or CleanUpAfterTest.

    Otherwise the first SDK call in the run performs setup. Failures during lease or Appium create fail the test immediately (NUnit error)—fix Settings or controller state before retrying.

    When the entire run completes (pass or fail), the device is returned automatically only if Release session after test run is checked in Settings. If that option is off, the lease stays until you use Release session now or turn the option back on for the next run.

    What “good” looks like

    • Unity Console: Test SDK: Test device session is ready. (or prior connect), then test logs/assertions.
    • Device: APK launches on first session create; UI responds to Editor-driven commands.
    • Settings shows Editor session — Ready for SDK calls in this domain after Connect test device succeeds.

    Troubleshooting

    Symptom Things to check
    Test SDK App path is empty… Set App path before running tests or Connect test device. Path must exist on the machine running the Test Controller.
    Test device assignment failed / lease message from controller No claimable device; wrong Selected device; another session holding the pool; controller not running. Refresh device list.
    Appium session was not created / message from controller Bad APK path, install failure, Appium/device error—read the exception text and controller logs.
    Appium session already active; skipping create Stale session on device. Release session now, Stop Test Server, or reinstall launch; then Connect test device again.
    Command hub is not connected APK without InAppTestRunner / automation define; wrong bundle id; app crashed; firewall blocking gRPC.
    Timed out waiting for object/scene Wrong path (Extract Object Path); increase timeout; game not on expected scene.
    Failed to click button Path not a Button; object inactive.
    Purchase failures PurchaseByButton / Purchase; sandbox account; up to 3 minutes for Purchase.
    RPC / type errors after upgrade Update com.lhh.testsdk and com.lhh.testcontroller.shared, re-run Install Test SDK, restart server, new APK.

    For controller-side logs, use Progress (Advance Settings) or ~/lhh-auto-test-controller/.run/ when using the installed controller repo.

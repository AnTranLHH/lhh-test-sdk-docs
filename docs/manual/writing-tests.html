    Writing test cases

    Tests are ordinary NUnit tests in the Unity Editor. They call static methods on LHH_TestSDK to control the game on a connected Android device.

    API details: Scripting API — LHH_TestSDK.

    Where to put tests

    Add a test assembly under your project, for example Assets/Tests/..., with references to Unity Test Framework and the Test SDK assemblies (follow how your game repo already sets up Edit Mode tests).

    Edit Mode vs Play Mode

    Most automation tests run in Edit Mode so the Editor drives the device while the game runs on hardware:

    [Test]
[RequiresPlayMode(false)]
public async Task Example_flow()
{
    await LHH_TestSDK.WaitForScene("Home", timeoutSeconds: 50f);
    await LHH_TestSDK.WaitForObject("iap_manager");
    await LHH_TestSDK.ClickButton("__VIEWS__/Shop/.../Button Open");
}

    Use async Task test methods and await every SDK call.

    Typical flow

    1. Wait for state — WaitForScene, WaitForObject (poll every 2 seconds until timeout).
    2. Act — ClickButton for normal UI; IAP shop buy flows use PurchaseByButton or Purchase.
    3. Assert — NUnit Assert.* on values from GetGameData, GetText, or your own helpers.

    Example reading PlayerPrefs on the device:

    string raw = await LHH_TestSDK.GetGameData("coin");
Assert.IsTrue(int.TryParse(raw, out int coins));
Assert.GreaterOrEqual(coins, 1000);

    Hierarchy paths (buttons and objects)

    Paths use / between hierarchy segments, same rules for WaitForObject, ClickButton, and GetText:

    • Root objects: path segment matches GameObject.Find.
    • Children: resolved with Transform.Find under the previous segment.

    Copy paths from the Editor:

    • LHH Test SDK → Extract Object Path
    • Or GameObject → LHH Test SDK → Extract Object Path with a object selected.

    Paste the copied string into your test constants. Real projects often use long paths under prefixes such as __VIEWS__/....

    UI clicks vs in-app purchase

    Goal API
    Tap a normal Unity UI button ClickButton(path)
    Tap shop buy + complete native store sheet PurchaseByButton(path)
    Purchase by store product id (no button path) Purchase(catalogProductId)

    Do not use ClickButton for IAP buy buttons that must trigger the native store UI—use PurchaseByButton.

    Logging during investigation

    These only write to the Unity Console; they do not talk to the controller:

    LHH_TestSDK.LogWithColor("checkpoint A", Color.cyan);
LHH_TestSDK.LogError("coins before assert: " + coins);

    Timeouts

    WaitForScene, WaitForObject, ClickButton, and GetText accept optional timeoutSeconds (default 30). Increase for slow loads or heavy scenes.
